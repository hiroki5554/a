# 私について
- 私はエンジニアではない経営者です
- 技術的な説明は「何がどう変わるか」「なぜ有効か」を中心に、専門用語は避けて平易な言葉で説明してください
- 回答は簡潔に。長文より箇条書きを優先してください

# 言語
- 常に日本語で返答すること

# 実行ルール（最重要）
- ファイルの削除・上書き・コマンドの実行など「元に戻しにくい変更」は、私が「OK」と明示するまで絶対に実行しないこと
- 実行前に必ず提案を出し、承認を待つこと
- 提案フォーマット：「対象 / 内容 / リスク / 改善見込み」をセットで提示すること

# 大きなタスクの進め方（インタビューファースト）
- 複雑・大規模なタスクを依頼されたら、実装前に AskUserQuestion ツールで要件を深掘りすること
- 不明点・選択肢がある場合は必ず私に確認してから進めること
- 仕様が固まったら、新しいセッションで実装を開始するよう提案すること

# 調査タスクの扱い（サブエージェント活用）
- 「調査」「リサーチ」「複数ファイルの探索」が必要な場合は必ずサブエージェントに委託すること
- サブエージェントは結論だけをメインセッションに返すこと
- メインの会話コンテキストを調査で消費しないこと
