# write-draft：記事下書き生成スキル

## 実行手順

1. ユーザーからテーマ・媒体・想定読者・文字数を確認する（未指定は質問する）
2. 必要に応じて `/trend-check` でトレンド情報を事前収集する
3. 記事の構成案（見出し構造）を作成し、ユーザーに確認を取る
4. 承認後、下書きを執筆する
5. `/home/user/business/output/articles/YYYY-MM-DD_{タイトル}.md` として保存する
6. 保存完了を報告し、タイトル候補を3案提示する

## 確認する情報

| 項目 | 例 |
|------|-----|
| テーマ | AIを使った業務効率化 |
| 媒体 | note / LinkedIn / 自社ブログ |
| 想定読者 | 中小企業の経営者 |
| 文字数 | 2000字・3000字・5000字 |
| トーン | 丁寧・カジュアル・専門的 |

## 出力フォーマット

```markdown
# {タイトル}

## リード（導入文）
...

## {見出し1}
...

## {見出し2}
...

## まとめ
...

---
タイトル候補：
1. 
2. 
3. 
```

## 注意事項
- 構成案を必ずユーザーに確認してから本文を書く
- クライアント名・個人情報は含めない
- 事実として書く場合はソースを明記する
- 下書きはあくまで叩き台。最終確認はユーザーが行う
